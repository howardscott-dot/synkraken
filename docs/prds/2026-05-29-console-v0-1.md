# SynKraken Console v0.1 PRD

Date: 2026-05-29

## 1. Objective

Create SynKraken Console v0.1 as a Tauri v2 desktop app in `apps/console/`.
The Console is a dark, dense operator client for the existing SynKraken daemon.
It provides desktop access to workforce health, proposals, proposal detail,
trace inspection, latest incident context, dead letters, and a small command
palette.

SynKraken remains one open-source product. The Python daemon remains
authoritative, SQLite remains daemon-owned, and Console consumes daemon HTTP
APIs at `http://127.0.0.1:9460` by default.

## 2. Problem Being Solved

Operators currently have CLI, TUI, and local Web Command Deck surfaces. A
desktop Console gives SynKraken a native local operator shell without replacing
those surfaces or creating a second backend. The v0.1 slice focuses on the
most control-plane-native operational work:

- seeing which workers are enabled, degraded, failing, disabled, or
  registry-only
- reviewing execution-authority proposals
- approving, rejecting, or executing proposal records through the daemon
- inspecting trace and incident data
- navigating core screens quickly with `Ctrl+K`

## 3. Non-Goals

- Do not replace the CLI, TUI, or existing Web Command Deck.
- Do not rewrite the daemon.
- Do not split SynKraken into core, pro, commercial, or cloud editions.
- Do not add auth, accounts, remote hosting, cloud sync, or external backend
  services.
- Do not duplicate daemon logic or read/write SQLite directly.
- Do not add fake production data when daemon APIs exist.
- Do not build all Stitch screens.
- Do not introduce heavy state management.
- Do not add proposal actions beyond existing daemon endpoints.

## 4. User/Operator Workflow

1. Operator starts the SynKraken daemon separately.
2. Operator launches Console from `apps/console` or the repo-root npm script.
3. Console checks daemon health at the configured daemon URL.
4. If daemon is unavailable, Console shows an offline state with the target URL
   and refresh affordance.
5. Operator uses the left navigation or `Ctrl+K` command palette to open:
   Workforce, Proposals, Trace, or Incidents.
6. Workforce view loads daemon-reported workers and runtime health signals.
7. Proposals view lists all and pending proposals; operator can approve,
   reject, execute, or open detail.
8. Proposal detail shows metadata, governance reason, execution payload, and
   event timeline before actions.
9. Trace Explorer accepts a trace id and displays daemon trace output.
10. Incidents view shows the latest incident and dead letters where available.

- `GET /v1/workforce`
- `GET /v1/workforce/health`
- `GET /v1/proposals`

- `POST /v1/proposal/reject`

- `GET /v1/incident/latest`

No daemon APIs should be changed for v0.1. No direct SQLite access is allowed.

## 8. Acceptance Criteria

- Console exists at `apps/console/` and uses Tauri v2, React, TypeScript, and
  Tailwind.
- Console defaults to `http://127.0.0.1:9460` and exposes that value through a
  small config constant or environment-supported frontend constant.
- Console uses a typed fetch API client in `src/lib/api.ts` with clear errors
  and practical request timeouts.
- App Shell is dark only, dense, and uses matte near-black surfaces, cyan
  operational accents, amber warning accents, sharp `1px` borders, and
  monospace operational text.
- Offline daemon state is visible and does not crash the app.
- Workforce view consumes daemon data and distinguishes enabled adapter
  workers, disabled workers if surfaced, and registry-only runtimes if surfaced
  by the workforce payload.
- Proposals view lists proposals and pending proposals and supports approve,
  reject, and execute via daemon endpoints.
- Proposal detail consumes `GET /v1/proposal/{id}` and shows metadata,
  governance reason, execution payload, and proposal events.
- Trace Explorer consumes `GET /v1/trace/{id}` from user input and displays
  replay summary, raw timeline, messages, deliveries, dead letters, linked
  decisions, handoffs, proposals, and memory markers when present.
- Incidents view consumes latest incident and dead letters. Retry/replay
  controls are only shown if implemented against known existing endpoints.
- Command Palette opens with `Ctrl+K` and includes Go to Workforce, Go to
  Proposals, Go to Trace, Refresh, Open daemon health, and Open latest incident.
- Docs explain what Console is, how it connects to the daemon, how to run it,
  consumed APIs, and v0.1 limitations.
- No fake production data is used when daemon data exists.
- Existing Python package behavior is not broken.

- The app assumes the SynKraken daemon is already running at the configured
  URL.
- Runtime registry distinction depends on fields present in the daemon
  workforce payload.
- The Tauri build cannot complete in this environment until required Linux
  WebView/desktop system packages are installed.
